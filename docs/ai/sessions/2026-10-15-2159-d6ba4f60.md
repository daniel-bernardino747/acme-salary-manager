**Q1: How does each repository and HTTP test start from a clean, known dataset?**

**My recommendation:**
- **Repository tests** create a fresh migrated `:memory:` database per test, using `createDb(':memory:')`. The migration is a handful of statements and costs about a millisecond, so full isolation is basically free.
- **HTTP tests** boot one Nest app per test file, which takes roughly 50–100 ms with SWC. Before each test, a `clearEmployees(db)` step deletes all employee rows and clears `sqlite_sequence`. This is the same clearing `--reset` already does, as one shared function. The test then inserts its own rows with the builder.

**Why:** This keeps the suite in the low seconds without wrapping tests in transactions. Rolling back each test would interfere with the FTS triggers and with any service that opens its own transaction. Booting a fresh Nest app for every test would make startup cost grow with the number of tests. It also means the reset path the seed relies on gets tested on every run.

**Alternative:** a fresh Nest app per test (simplest, but slower as the suite grows).
